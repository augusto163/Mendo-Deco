ETAPA 1: INPUT BINARIO (CLIENT-SIDE) Archivo: src/components/BambuFarmDashboard.tsx

El evento Drag & Drop recibe un objeto Blob / File en memoria

En HTML5, cuando arrastras un archivo al navegador, la API de File no sube nada a internet. El navegador crea un apuntador en memoria RAM (File extends Blob). En aplicaciones tradicionales se enviaba este archivo con un POST multipart/form-data a un servidor PHP/Python. Pero en nuestra arquitectura, se procesa en el hilo del cliente para dar respuesta en milisegundos sin consumir ancho de banda de red.

Concepto de Ingeniería:

I/O Asíncrono en el Cliente: Se usa la interfaz FileReader o el stream del archivo directamente en el motor V8 de JavaScript, evitando latencia de red (Network RTT = 0ms).

Código en ejecución real TypeScript / JS 
// 1. El usuario suelta el archivo pikachu_p1s.3mf
const onDrop = async (e: React.DragEvent) => {
  const file = e.dataTransfer.files[0];
  console.log(file.name); // "pikachu_p1s.3mf"
  console.log(file.size); // 12,450,200 bytes (~12 MB)
  console.log(file.type); // "application/zip" o "model/3mf"

  // Llamamos a nuestro parser en src/utils/bambuParser.ts:
  const metadata = await parseBambu3mf(file);
};

🏛️ El Stack del Sistema: ¿Qué está hecho y qué falta?

Como futuro Ingeniero en Sistemas, piensa el software en capas de abstracción:

1. Capa Física & Laminador (Hardware) EXTERNO

Impresoras Bambu (P1S, X1C, A1) + Bambu Studio

El usuario lamina el modelo 3D en Bambu Studio. Bambu calcula los caminos del extrusor, el tiempo estimado y el consumo de filamento, y empaqueta todo en un archivo .3mf.

2. Capa Presentación & Lógica Cliente (SPA) 100% IMPLEMENTADO

Next.js 14 + React 18 + Tailwind + JSZip

La interfaz gráfica (UI) vive aquí. Contiene el visualizador de costos, el módulo de advertencias de stock, y el algoritmo que descomprime el .3mf en memoria.

¿Por qué funciona sin servidor? Porque es una SPA (Single Page Application). El navegador descarga el HTML/JS una sola vez y ejecuta toda la lógica localmente.
3. Capa de Negocio & Servidor (Backend API) PENDIENTE

API REST o GraphQL (Next.js Server Actions o Node/Express)

Esta capa todavía no existe. Su responsabilidad futura será: autenticación de usuarios (login), recibir pedidos de clientes, enviar órdenes de impresión a las máquinas por red (MQTT Bambu) y guardar datos persistentemente.

4. Capa de Persistencia (Base de Datos) PENDIENTE

PostgreSQL / SQLite + Prisma ORM

Aquí se guardarán en disco tus tablas relacionales: Clientes, Pedidos, Bobinas y Impresoras. Ahora mismo, si refrescas la web, se pierden los cambios porque no hay BD.

💡 Pregunta Clave: ¿Por qué empezamos por el Frontend?

En ingeniería de software moderno existe la metodología Prototipado Vertical / Lean:

  • Validar el riesgo técnico más complejo: El mayor desafío técnico era saber si podíamos descomprimir y extraer en milisegundos los datos de Bambu Studio directamente en el navegador del operario sin saturar un servidor. ¡Y se logró!
  • Definir la UX y las Fórmulas: Antes de crear tablas en SQL, necesitábamos saber con precisión qué variables matemáticas intervienen (kW, vida útil, peso de purga del AMS, tiempos de setup).
  • El modelo ya está diseñado: En los archivos diagrama_clases.html ya diseñamos las entidades UML que se usarán exactamente para crear las tablas de la base de datos cuando hagamos el backend.

🔄 ¿Qué pasa hoy cuando cambias datos en la página?

Hoy en día, cuando agregas una bobina o cambias el margen de ganancia:

Memoria RAM del Navegador:
Usuario cambia valor ➔ React `setBobinas([...])`
➔ Virtual DOM re-evalúa la fórmula
➔ El DOM se repinta en pantalla.
⚠️ F5 (Recargar página) ➔ Vuelve al estado inicial.

Cuando conectemos el backend, ese setBobinas además enviará un fetch('/api/bobinas', { method: 'POST' }) para guardarlo en la Base de Datos.

📂 Anatomía del Proyecto: ¿Qué significa cada archivo?

Como estudiante de sistemas, aquí tienes la explicación de qué rol cumple cada tecnología y extensión de archivo:

src/utils/bambuParser.ts TypeScript Puro (.ts)

Módulo de Lógica de Negocio (Backend/Utils)

No contiene nada visual ni HTML. Es una clase/módulo de funciones puras. Recibe el archivo binario, llama a JSZip, navega el árbol de archivos con expresiones regulares y selectores XML, y extrae los datos de ingeniería de impresión.

src/components/BambuFarmDashboard.tsx React + TSX (.tsx)

Componente Visual & Controlador de Estado

La extensión .tsx significa TypeScript XML. Permite mezclar lógica de programación en JavaScript con etiquetas visuales (HTML interactivo). Aquí se maneja la vista del usuario, los formularios y la actualización reactiva.

package.json Manifiesto JSON

El Gestor de Dependencias del Proyecto

Es el equivalente a un requirements.txt en Python, un pom.xml en Java (Maven) o un Cargo.toml en Rust. Lista qué librerías necesita el proyecto y qué comandos se usan para ejecutarlo (npm run dev).

index.html HTML Monolítico

Versión Ejecutable Sin Entorno Node.js

Como no tenías Node.js instalado en tu PC, creamos este archivo para que no te quedes sin ver la aplicación. Empaqueta todo el HTML, Tailwind CSS y el lector de archivos en un único archivo que cualquier navegador abre con doble clic.

🚀 Plan de Ingeniería para Agregar el Backend y la Base de Datos

Estos son los 3 pasos de ingeniería necesarios cuando decidas dar el salto al backend:

1

Instalar Node.js en Windows

Node.js es el entorno de ejecución que te permite correr JavaScript y TypeScript como servidor en tu máquina, fuera del navegador. Con él instalado, podrás ejecutar npm install para descargar Next.js y React.

2

Implementar Base de Datos con Prisma ORM + SQLite / PostgreSQL

Usaremos el diseño que ya hicimos en diagrama_clases.html. Definiremos los esquemas para guardar pedidos, clientes, stock de bobinas e impresoras en un archivo SQLite local o base de datos PostgreSQL en la nube.

3

Crear API Endpoints (CRUD)

Crearemos rutas como GET /api/pedidos y POST /api/pedidos para que cuando el operario confirme una cotización de Bambu, se guarde permanentemente en la base de datos y descuente automáticamente los gramos de la bobina correspondiente.
